# Ask Me — Flexsin site assistant

A grounded chat assistant for flexsin.com. Flask backend, hybrid RAG over a local
vector store, answers generated by **Qwen3 on Groq**.

Content gets in through an admin panel at `/admin`: paste text or upload a
`.docx` / `.pdf` / `.txt` / `.md`, and it's chunked, embedded and searchable
immediately. The same panel lets you run a visitor question and see the exact
chunks retrieval would feed the model.

The assistant answers only from retrieved content, and client identities are
stripped both in the prompt and in code before anything reaches a visitor.

## Run it

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # add GROQ_API_KEY, and set ADMIN_TOKEN
python app.py
```

- Chat widget: `http://localhost:5000/`
- Admin panel: `http://localhost:5000/admin`

First run downloads the embedding model (~130MB) and seeds the store from
`data/knowledge.json`. If `ADMIN_TOKEN` isn't set, a random one is printed in the
startup log.

Tests (no network — the model call is stubbed, embeddings are faked):

```bash
pytest test_smoke.py -q
```

## Adding knowledge

**Through the panel** (`/admin`) — the normal path:

- *Paste text* for a block of copy, or *Upload file* for `.docx`, `.pdf`, `.txt`,
  `.md` (max 8MB). `.docx` tables are extracted too, since briefs often keep the
  real specs in a table.
- Give it a title and a type (`service` / `process` / `company` / `case_study` /
  `document`). Both are shown to the model with the chunk.
- **Test retrieval** in the right-hand card before trusting it. It shows each hit's
  semantic rank and similarity, its keyword rank, and the full chunk text. If a
  question returns nothing, the assistant will say it doesn't know — that panel is
  where you find out before a visitor does.
- *Remove* drops a source's chunks and vectors immediately.

**Through the seed file** — `data/knowledge.json` is the version-controlled
baseline. Edit it, then:

```bash
python check_kb.py          # validate entries
python seed.py              # add anything new
python seed.py --force      # re-embed all seed entries
```

Seeded entries and ingested ones live in the same index and rank against each
other; only their `origin` tag differs.

**Anonymize before you ingest.** Write case studies as industry + problem + stack
+ outcome, never a client name, brand, person or client URL. Add every real client
name and domain to `data/client_names.txt` — that list is redacted out of context
before the model sees it and out of answers before the visitor does, but it's a
safety net, not the primary control.

## How a turn works

1. **Hybrid retrieval.** The question is embedded and cosine-matched against every
   chunk, and separately scored by BM25. The two ranked lists are fused with
   Reciprocal Rank Fusion. Dense catches paraphrase ("iphone app" → "iOS and
   Android"); BM25 catches exact tokens dense models blur ("HL7", "SOC 2", version
   numbers). If the embedding model can't load, it degrades to keyword-only.
2. **No hits → no model call.** `app.py` returns the "I don't have specific
   information on that" line directly. Cheapest and most reliable way to enforce
   the grounding rule, and off-topic questions cost nothing.
3. Hits are scrubbed against `client_names.txt`, wrapped in a `CONTEXT` block, and
   sent with the system prompt plus the last three exchanges.
4. The reply has reasoning tags stripped, client names redacted, and any
   non-Flexsin URL removed before it goes back to the browser.

| [llm.py](llm.py) | Groq chat-completions client |
| [guardrails.py](guardrails.py) | `<think>` stripping, client-name and URL redaction |
| [seed.py](seed.py), [check_kb.py](check_kb.py) | Load and validate `data/knowledge.json` |
| [data/store/](data/store/) | The live index: `chunks.json` + `vectors.npy` |
| [templates/](templates/), [static/](static/) | Chat widget and admin panel |

## API

| Endpoint | Purpose |
| --- | --- |
| `POST /api/chat` | `{message, session_id}` → `{reply, session_id, sources, grounded}` |
| `POST /api/reset` | Clear a session's history |
| `GET /healthz` | Chunk/source counts, model ids, embedding status |
| `POST /api/admin/ingest` | JSON `{title, type, text}` or multipart `file` |
| `GET /api/admin/sources` | List indexed sources |
| `DELETE /api/admin/sources/<id>` | Remove a source |
| `POST /api/admin/search` | `{query}` → ranked chunks, no LLM call |

Admin routes take `X-Admin-Token`.

## Choosing a Groq model

Model availability changes. List what your key can actually reach:

```bash
curl -s https://api.groq.com/openai/v1/models \
  -H "Authorization: Bearer $GROQ_API_KEY" | python -m json.tool | grep '"id"'
```

Set the one you want as `GROQ_MODEL`. Qwen3 is a reasoning model, so `llm.py`
sends `reasoning_format: "hidden"` and `guardrails.py` strips `<think>` blocks
defensively — keep both if you switch to another reasoning model.

## Sharing a public link

This machine sits behind NAT, so nginx alone doesn't make the app reachable —
nginx is the local front door, and a tunnel provides the public URL.

```bash
sudo ./deploy/setup-nginx.sh   # once: installs nginx, enables the site
./deploy/share.sh              # starts gunicorn + prints a public URL
```

`share.sh` refuses to open the tunnel unless `/admin` returns 404 on the public
listener, so a misconfigured proxy can't quietly publish the admin panel.

**The proxy splits the app across two ports** ([deploy/askme.nginx.conf](deploy/askme.nginx.conf)):

| Listener | Reaches | Who |
| --- | --- | --- |
| `:80` | chat only — `/admin` returns 404 | the public / the tunnel |
| `127.0.0.1:8081` | everything, including `/admin` | you, locally |

That split matters. An IP allowlist on `/admin` would **not** work behind a
tunnel: ngrok and cloudflared deliver every request from `127.0.0.1`, so
`allow 127.0.0.1` would hand the panel to the entire internet. Separate ports
mean the public listener has no route to it at all.

Belt and braces: `ADMIN_ENABLED=0` un-registers the admin routes in the app
itself. Set it on any process exposed without a proxy in front.

### Before you share

- **Cost.** A public link means strangers can spend your Groq tokens. nginx caps
  chat at 30 req/min per IP and the app caps 20; both read the real client IP
  from `X-Forwarded-For`. Watch your Groq dashboard while a link is live.
- **Content.** Whatever is in the store is what visitors are told. Confirm it's
  real before sharing — `python check_kb.py` lists everything indexed.
- **The URL is public and unguessable, not private.** Anyone with the link gets
  in. `ngrok http --basic-auth user:pass 80` adds a password.

Running it as a service instead of a terminal you have to keep open:

```bash
.venv/bin/gunicorn -c gunicorn.conf.py wsgi:app   # foreground
```

`gunicorn.conf.py` pins `workers = 1` deliberately: the vector store and session
history are per-process memory, so a second worker would hold its own copy and
uploads would vanish depending on which one served the request. Scale with
`GUNICORN_THREADS` until the store moves to a shared backend.

## Before production

- `data/store/` is durable state and the **only** copy of pasted/uploaded content.
  Back it up. It's gitignored because the vector matrix churns badly in git.
- Sessions and rate-limit counters live in process memory. Move both to Redis
  before running more than one worker; the store itself is per-process too, so
  multi-worker needs a shared backend (Qdrant, pgvector) rather than the .npy.
- Serve behind gunicorn and a reverse proxy; the app reads `X-Forwarded-For`.
- Put `/admin` behind your VPN or SSO in addition to the token.
- Log questions that return `grounded: false` — they are your content gaps.
